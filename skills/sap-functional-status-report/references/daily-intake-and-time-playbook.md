# Daily Intake and Time Playbook

## Minimal intake fields

### Demand identity
- Client
- WI/CR/GAP/INC or known identifier
- Short demand name

### Timeline
- Received date
- Start date
- Expected delivery, if defined

### Today
- What was done
- Time block/duration
- Meetings/KT/alignment
- Ad-hoc work

### Current state
- Current stage
- What is completed
- What remains
- Blocker yes/no
- Blocking dependency if any

### Next step
- Immediate next action
- Dependency
- Delivery expectation change yes/no

### Management
- Schedule risk
- Decision required
- Priority change

## Ask only what is missing

If the user already supplied client, demand, work, time, blocker, and next step, do not repeat these questions.

## Time examples

Accepted:
- 09h-10h meeting
- 10h-12h EF review
- morning on CR80, approx 3h
- 2h test execution

## Time gap

If 6h are accounted in an 8h closeout:

> Faltam 2h para fechar a matemática do dia. O que aconteceu nesse período?

Do not guess lunch, meeting, or idle time.

## Overlap

If the user says:
- 9h-12h CR80
- 10h-11h client meeting

Ask whether the meeting is included in the 9h-12h block. Do not count 4h automatically.

## Partial day

If explicitly partial:
> Status parcial até 14h - 5h contabilizadas.

Do not force 8h.
